# 목표(기업→부서→개인) 계층 달성률 + 개인 로그인 마이페이지 설계

- 작성일: 2026-08-03
- 관련 파일: `index.html`, `sql/001_schema.sql`, `handlers/okrs/*`, `handlers/public-data.js`, `handlers/_lib/*`

## 배경

현재 `okrs` 테이블/화면은 회사·조직·개인 3단계 레벨과 `parent_id` 자기참조는 갖고 있지만, 각 목표의 진척률(`progress`)은 슬라이더로 사람이 직접 입력하는 값이다. 상위 목표가 하위 목표들의 실제 달성 현황을 반영하지 않고, 개인이 오늘 무엇을 했는지 체크하는 개념도 없다.

이번 작업은 "기업이 분기 목표를 세우면 부서가 매달 그중 하나를 골라 하부 목표를 만들고, 개인은 그 부서 목표 아래 할 일을 체크하면 개인→부서→기업 달성률이 자동 집계"되는 구조를 만든다. 더불어, 지금은 인사팀 공유 비밀번호로만 잠겨 있는 인사 시스템에 개인별로 "내 목표/평가/원온원"만 볼 수 있는 개인 로그인(마이페이지)을 추가한다.

## 범위

- 목표 계층 데이터 모델 확장(월 단위 부서/개인 목표, 개인 목표 체크리스트) + 달성률 자동 계산
- 성과 대시보드에 기업 목표(월별 포함)·부서별 달성률 노출
- 이메일 기반 무비�번호 개인 로그인 + "마이페이지"(내 목표/내 평가/내 원온원)
- 제외: 팀장 권한 세분화, 부서 목표 승인 플로우, 비밀번호 재설정/보안 강화(모두 후속 과제)

## 아키텍처

기존과 동일한 패턴을 그대로 따른다 — 정적 `index.html`이 `/api/*` 서버리스 함수를 호출하고, 화면은 한 번에 받아온 `DB` 객체를 클라이언트에서 렌더링/집계한다. 새로 추가되는 것은:

```
index.html
  ├─ (기존) 공개 성과관리 데이터 fetch — /api/public-data
  ├─ (신규) 로그인 — POST /api/member-login { email } → Set-Cookie
  └─ (신규) 마이페이지 데이터 — 로그인 쿠키로 GET /api/my-page
                │
                ▼
        Vercel Serverless Functions ── Neon Postgres
```

달성률 집계는 **DB에 저장하지 않고 매번 클라이언트에서 계산**한다 (인원 규모상 트리거/배치 없이도 충분하고, 기존 9-그리드/대시보드 KPI들도 같은 방식). 서버는 원본 데이터(okrs, okr_tasks)만 그대로 내려준다.

## 데이터 스키마 변경

```sql
-- okrs: 계층/기간 정보 보강
ALTER TABLE okrs ADD COLUMN month text;   -- 'YYYY-MM'. 레벨='조직'|'개인'일 때만 사용, '회사'는 quarter만 사용
ALTER TABLE okrs ADD COLUMN member_id uuid REFERENCES members(id) ON DELETE SET NULL; -- 레벨='개인'일 때 소유자

-- 개인 목표의 체크리스트 (신설)
CREATE TABLE okr_tasks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  okr_id uuid NOT NULL REFERENCES okrs(id) ON DELETE CASCADE,
  title text NOT NULL,
  done boolean NOT NULL DEFAULT false,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

기존 `progress`/`unit`/`target` 컬럼은 삭제하지 않는다(마이그레이션 리스크 최소화). 다만 새 화면은 이 컬럼들을 더 이상 쓰지 않고 항상 계산값을 표시한다. `members.password_hash` 같은 별도 인증 컬럼은 추가하지 않는다 — 로그인은 기존 `members.email`만으로 처리한다(아래 인증 항목 참고).

### 레벨별 필드 사용 규칙

| 레벨 | quarter | month | owner | member_id | parent_id |
|---|---|---|---|---|---|
| 회사 | '2026-Q3' | (안 씀) | '전사' 고정 | (안 씀) | (안 씀) |
| 조직(부서) | quarter는 month로부터 자동 계산 | 'YYYY-MM' | 팀명 | (안 씀) | 회사 목표 id |
| 개인 | 부서 목표와 동일값 상속 | 부서 목표와 동일 | (안 씀, member_id로 대체) | 로그인한 본인 | 부서 목표 id |

**부서 목표 개수 제한**: 같은 팀(owner)·같은 달(month)에 이미 3개가 있으면 생성 차단 (클라이언트 검증 + 서버 핸들러에서 카운트 재검증).

## 달성률 계산 로직 (클라이언트, 매 렌더마다 재계산)

```
개인목표 달성률(o)   = tasks.length ? round(100 * done수/전체) : 0
부서목표 달성률(o)   = 그 부서목표를 parent로 둔 개인목표들의 평균 (없으면 0)
기업목표 "이번달" 달성률 = 그 기업목표를 parent로 둔, 해당 월(month)의 부서목표들의 평균
기업목표 "분기" 달성률   = 그 기업목표 아래 분기 내 존재하는 모든 부서목표(최대 3개월×N부서)의 평균
```

대시보드는 기업목표 카드마다 분기 평균 숫자 + 월별 막대(예: 8월 62%·9월 70%·10월 -)를 함께 보여준다. 부서별 달성률 목록도 같은 계산식의 부서목표 평균을 사용한다.

## 개인 로그인 ("마이페이지")

- **인증 방식**: 비밀번호 없음. `members.email`과 정확히(대소문자 무시) 일치하는 이메일을 입력하면 그 구성원으로 로그인 처리. 이메일은 인사팀이 구성원 등록/수정 화면에서 미리 입력해둬야 함.
- `POST /api/member-login { email }` → 일치하는 구성원 있으면 세션 쿠키 발급, 없으면 401 `{ error: '등록된 이메일이 아니에요' }`
- **세션**: 새 의존성 추가 없이 Node 내장 `crypto.createHmac`으로 서명한 쿠키 토큰(`memberId + 만료시각`) 발급. `Set-Cookie: session=...; HttpOnly; SameSite=Lax`. 이후 요청은 같은 오리진이라 브라우저가 자동 전송.
- `POST /api/member-logout` → 쿠키 삭제
- 개인 목표 관련 쓰기 API(체크리스트 토글/추가/삭제, 개인 목표 생성)는 세션에서 얻은 `memberId`를 그대로 소유자로 사용 — 요청 바디로 받은 member_id는 신뢰하지 않는다(다른 사람 것을 건드리지 못하게).
- **마이페이지 화면 구성** (nav에 "마이페이지" 신규 추가, 기존 인사 비밀번호와 무관):
  - 로그인 전: 이메일 입력 폼 하나
  - 로그인 후:
    - 이번 달 내 목표 체크리스트(추가/체크/삭제) + "내 목표 달성률 / 우리 팀 이번 달 달성률 / 우리 회사 이번 분기 달성률" 3개 숫자
    - 내 목표 → 부서 목표 → 기업 목표로 이어지는 연결 트리
    - **내 평가 기록** — 분기별로 내가 받은 평가(공동·리드·직무·성과·커스텀, 강점/보완점, 캘리브레이션 확정 등급)
    - **내 원온원 기록** — 날짜별 면담 노트
  - 평가/원온원 데이터는 이미 `public-data`에 전사 데이터로 내려오고 있으므로, 새 백엔드 없이 로그인한 `memberId`로 클라이언트에서 필터링만 하면 된다.

## API 변경/신설 요약

| 엔드포인트 | 설명 |
|---|---|
| `POST /api/okrs` (기존, 확장) | `level`이 '조직'이면 month+parent(회사목표) 필수, 팀당 월 3개 제한 검증. '개인'은 이 엔드포인트로 생성하지 않음 |
| `POST /api/my-goals` (신규) | 로그인 세션 필요. 개인 목표 생성 (parent=부서목표, month는 부서목표에서 상속) |
| `POST /api/okr-tasks`, `PATCH /api/okr-tasks/:id`, `DELETE /api/okr-tasks/:id` (신규) | 로그인 세션 필요. 소유자 본인 개인목표에 속한 task만 허용 |
| `POST /api/member-login`, `POST /api/member-logout` (신규) | 이메일 로그인/로그아웃 |
| `GET /api/public-data` (기존, 확장) | `okrs`에 `month`, `member_id` 포함. `okr_tasks` 배열 추가(전사 공개 — 달성률 계산용. 체크리스트 제목 자체가 민감하지 않다는 전제) |

## 화면 구성 변경 요약

- **목표 페이지** (로그인 불필요, 기존 관리 화면 성격 유지): 기업 목표(분기) 등록, 부서 목표(월별, 팀당 3개 제한) 등록만 담당. 개인 목표 생성 UI는 여기서 제거하고 마이페이지로 이동.
- **성과 대시보드** (기존, 로그인 불필요): 기업목표 달성률(월별 막대 포함) 카드 + 부서별 달성률 목록 추가.
- **마이페이지** (신규, 이메일 로그인 필요): 위 인증 항목 참고.

## 리스크 / 후속 과제

- 이메일만으로 로그인하는 방식은 동료의 회사 이메일 주소를 아는 사람이면 그 사람 마이페이지를 열 수 있다는 뜻이다 — 사용자가 명시적으로 요청한 트레이드오프이므로 이번 범위에서는 그대로 두되, 실사용 중 문제가 되면 비밀번호/2차 인증 추가를 후속 과제로 남긴다.
- 부서 목표 생성 권한(현재: 로그인 없이 아무나 목표 페이지에서 생성 가능)을 팀장으로 제한하는 것은 이번 범위 밖 — 실사용해보고 필요하면 추가.
- `okr_tasks`를 공개 API(`public-data`)에 그대로 노출하는 것은 체크리스트 문구가 민감할 수 있는 팀에서는 재검토가 필요할 수 있음.
