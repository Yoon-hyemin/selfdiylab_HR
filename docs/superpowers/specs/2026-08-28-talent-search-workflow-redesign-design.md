# 인재검색 자동화 — 화면 구조를 5단계 흐름으로 재구성 설계

- 작성일: 2026-08-28
- 관련 기존 문서: `docs/superpowers/specs/2026-08-28-talent-search-auto-search-execution-design.md`(2단계에 해당하는 검색실행 자동화, 이 재구성과 별개로 이미 계획됨)

## 배경

지금까지 인재검색 자동화의 개별 기능(Level1 필터, 자동 페이지 넘김, 직무60점 채점)은 각각 잘 동작하는데, 사용자(윤혜민)가 실제로 써보니 **화면 구조 자체가 문제**라고 지적했다: "설정한 건 어디로 숨는지 안 보이고, 수집된 사람을 보는 화면도 굉장히 밑에 숨어있어서 아는 사람만 쓸 수 있다."

사용자가 직접 정리한 실제 필요한 흐름은 다음 5단계다.

1. 기준을 정해서 저장하기 (사람)
2. 사람인 버튼을 눌러서 검색 실행하기 (사람)
3. 수집하기 (시스템)
4. 수집된 인원을 조건에 맞게 적합/부적합 표시하기 (시스템)
5. 이력서 확인하기 (사람)

**5단계 기능 자체는 이미 다 만들어져 있다** — 문제는 이게 대시보드/기준관리센터/버전이력/실행엔진연결 탭 + "카드 클릭 → 상세 화면 → 한참 스크롤해야 나오는 '검색 진행 보기' 버튼" 이라는 구조 안에 흩어져 있다는 것이다. 이번 작업은 새 기능을 만드는 게 아니라 **이미 있는 기능들을 저 5단계 흐름에 맞춰 화면을 다시 배치**하는 것이다.

시각 자료(브라우저 목업)로 두 방향을 비교하고 사용자가 확정: **목록 화면은 카드마다 지금 몇 단계인지 배지로 보여주고, 카드를 클릭하면 그 프로젝트 전용의 세로 5단계 화면이 열리는 구조**(대시보드는 목록 역할만, 탭 없이 진행). 디자인은 "토스처럼 깨끗하고 깔끔하게" — 새 색상을 만들지 않고 이 사이트가 이미 쓰는 색·폰트·둥근 카드 스타일(`--primary`, `--card`, `--border` 등 기존 CSS 변수) 그대로, 완료/진행중/대기 상태를 색상 강도와 굵기 차이만으로 구분한다.

## 이번 슬라이스 범위

**포함**:
- "인재검색" 대시보드를 프로젝트 카드 목록(각 카드에 현재 단계 배지)으로 재구성.
- 프로젝트 카드를 클릭하면 열리는 새 화면: 5단계를 세로로 나열, 각 단계는 완료(초록 체크)/진행중(강조 테두리)/대기(흐린 회색) 상태로 표시하고, 그 단계에 해당하는 기존 기능(조건 요약, 사람인 검색 안내, 수집 진행률, 적합/부적합 표, 이력서 링크)을 그 카드 안에 인라인으로 보여준다.
- 기존에 따로 있던 3개 화면(검토 화면, 검색 진행 화면, 실제 후보 리스트)을 이 하나의 세로 화면으로 통합 — 별도 페이지 이동 없이 한 화면 안의 단계별 섹션이 된다.
- "기준 관리센터"/"버전 이력"/"실행엔진 연결"은 프로젝트 하나에 속한 게 아니라 회사 전체 공용 설정이므로, 목록 화면과 분리해서 별도 진입점(예: 목록 화면 우측 상단 "⚙ 설정")으로 옮긴다 — 화면 자체는 그대로, 진입 경로만 바뀐다.
- "새 인재검색" 입력 폼 필드 정리(아래 절 참고) — 자동화(검색·채점·필터)에 실제로 쓰이는 것과, 다른 화면에서 실제로 쓰이는 것만 남기고, 어디에도 안 쓰이는 것은 삭제.
- 남는 필드는 용도(🔍 검색용 / ⭐ 채점용 / 📥 가져오기 필터용)를 라벨로 명시해서, 사용자가 "이 항목을 왜 입력하는지" 알 수 있게 한다.

**제외**:
- 새로운 자동화 기능 추가 없음 — 이미 있는 기능을 재배치하는 것.
- 사람인 검색 실행 자동화(FILL_AND_SEARCH) 자체는 별도 설계 문서(`2026-08-28-talent-search-auto-search-execution-design.md`)에서 이미 다룸 — 이번 문서는 그 기능이 "2단계" 자리에 화면상 어떻게 노출되는지만 다룬다.

## 새 인재검색 입력 폼 — 필드 정리

사용자와 함께 필드별 실제 용도를 확인한 결과:

**남기는 필드**:
- 검색 프로젝트명(title) — 목록 카드 식별용.
- 필수/OR/정확일치/제외 키워드 — 🔍 **검색에 사용**(사람인 AND/OR/NOT칸에 자동으로 채워짐).
- 우대 키워드 — ⭐ **채점에만 사용**(직무60점 근거수준 추정 신호, 검색엔 안 씀).
- 희망 경력 최소/최대 — 📥 **가져오기 필터에 사용**(Level1, 범위 밖이면 저장 자체를 안 함).
- 총 적합 추천 목표 인원 — 가상 후보 생성 개수 계산과 대시보드 진행률(단계 배지의 "OO/목표") 양쪽에 실제로 쓰인다. 처음엔 "확장에 별도 목표인원 입력칸이 있어서 중복"이라고 오판했으나, 실제로 다른 용도로 쓰이고 있어서 유지하기로 확정.
- 검색할 플랫폼 — 지금 실제로 동작하는 사람인만 선택지로 남긴다(잡코리아/원티드/리멤버는 아직 아무 기능이 없어서 체크해도 의미가 없다 — 나중에 그 플랫폼 확장이 실제로 만들어지면 다시 노출).

**삭제하는 필드** (전부 자동화에 안 쓰이고, 아래 화면 재구성으로 카드/요약에 표시할 필요도 없어짐):
- 채용 직무/포지션명, 직급/역할수준, 고용형태, 채용인원, 근무지역
- 찾고 싶은 사람(자연어 설명) — 이 필드가 30자 미만이면 뜨던 "추가질문" 팝업 트리거도 함께 제거한다(이 필드 자체를 없애므로 그 판단 기준도 의미가 없어짐 — 키워드 미입력 시 뜨는 다른 추가질문은 그대로 유지).
- 상세조건 5개(입사가능시점/연봉/근무형태/필수자격/피해야할경력유형) — 애초에 "선택, 안 채워도 감점되지 않아요"로 안내하던 필드로, 실제로 아무 기능에도 연결된 적이 없다.

**DB/서버에 영향**: `role_title`은 지금 `NOT NULL` 제약이 있어서 입력을 없애려면 마이그레이션으로 제약을 풀어야 한다(`sql/022`). `target_recommend_count`는 유지하므로 그대로 둔다. 나머지 삭제 필드(`seniority_level`/`employment_type`/`headcount`/`location`/`natural_language_brief`/`work_conditions`)는 원래 nullable이라 스키마 변경 없이 그냥 입력을 안 보내면 된다. 서버 검증(`talentSearchProjectValidate.js`)에서 `roleTitle`/`employmentType`/`headcount` 필수 체크를 제거한다.

## 새 화면 구조

### 목록 (기존 "대시보드")

카드 하나 = 프로젝트 하나. 각 카드에 제목 + 현재 단계 배지.

**단계 판정 규칙**(서버에 새로 저장하는 값 없이, 이미 있는 데이터로 클라이언트가 매번 계산 — 이 프로젝트의 기존 원칙 그대로):

| 상태 | 판정 조건 |
|---|---|
| 1단계 · 조건 설정 | `status === 'draft'` |
| 2단계 · 사람인 검색 대기 | `status === 'approved'` 이고 실제 후보 리스트가 0명 |
| 3단계 · 수집 중 | 실제 후보가 1명 이상이고, 그중 "추천" 판정 인원이 `targetRecommendCount` 미만 |
| 4단계 · 적합/부적합 확인 중 | "추천" 판정 인원이 `targetRecommendCount` 이상 도달 |

**2단계 "검색 실행 여부"는 서버가 직접 알 방법이 없다** — 크롬 확장이 사람인에서 검색을 실행하고 나면 그 결과로 바로 후보를 저장하지, "검색을 실행했다"는 사실 자체를 별도로 기록하지 않는다. 그래서 "실제 후보가 1명이라도 들어왔는지"를 2→3단계 전환의 근거로 쓴다 — 검색 실행 자체를 서버가 확인하는 게 아니라 그 결과(후보 유입)로 간접 판단하는 것임을 명확히 해둔다.

**5단계(이력서 확인)는 별도 화면 상태가 아니다** — 4단계 화면(적합/부적합 표) 안에서 이름을 클릭하면 바로 원문 이력서로 이동하는, 이미 있는 동작이다. 억지로 "5단계 완료"라는 상태를 만들지 않는다(언제 이력서를 다 확인했다고 판단할지 정의할 방법이 없다 — 그건 사람의 판단 영역).

### 프로젝트 상세 (새 화면, 카드 클릭 시)

세로로 5개 블록(1~4단계 + 5단계 안내는 4단계 블록 안에 포함):

1. **조건 설정** — 완료되면(승인됨) 요약(키워드 5종, 경력범위, 목표인원)만 간단히 보여주고 "조건 보기"만 가능(승인 후엔 되돌릴 수 없다는 기존 정책 그대로라 "수정"은 없음). `draft` 상태면 지금 있는 입력 폼(정리된 버전) + "이 조건으로 검색" 승인 버튼.
2. **사람인 검색** — 완료 전이면 "크롬 확장에서 '목표 인원 채우기'를 눌러주세요" 안내(연결 코드 발급 상태도 여기서 확인 가능하게 링크). 완료 후(후보 1명 이상)면 마지막으로 가져온 시각 정도만 짧게 표시.
3. **수집 중** — 지금 "실제 후보 리스트" 표의 진행률 부분(추천 인원 수 / 목표인원)만 요약, 진행률 바.
4. **적합/부적합 확인** — 지금 "실제 후보 리스트" 표 전체(직무60점, 판정, 더보기, 정렬) — 이름 클릭하면 이력서로 이동한다는 안내 문구 포함.

기존 "가상 후보" 관련 화면(Level1/공통40점/직무60점 시뮬레이션)은 이번 재구성 대상이 아니다 — 그 기능은 실제 채용 흐름과 무관한 미리보기 도구라서, 이 5단계 화면에는 안 들어가고 그대로 별도로 유지한다(어디에 남겨둘지는 구현 단계에서 자연스러운 자리를 찾는다 — 예: 위 3번 블록 옆 보조 링크 정도).

### 설정 (분리)

"기준 관리센터"/"버전 이력"/"실행엔진 연결" 3개 화면은 그대로 두고, 진입 경로만 목록 화면 상단의 별도 버튼/메뉴로 옮긴다.

## 시각 스타일

새 색상·컴포넌트 라이브러리를 도입하지 않는다. 이미 있는 CSS 변수(`--primary`(#12B76A 초록), `--primary-light`, `--card`, `--border`, `--sub`)와 `border-radius`/`box-shadow` 관례를 그대로 쓴다. 상태 표현: 완료=초록 원+체크, 진행중=연한 초록 테두리 강조, 대기=회색 원+흐린 텍스트. 한 화면에서 지금 해야 할 액션(진행중 단계의 버튼)만 눈에 띄게, 나머지는 톤을 낮춘다.

## 테스트

- 자동화 로직 변경은 없고 화면 재배치+필드 삭제이므로, `node --test`로 커버되는 서버 쪽 순수 로직은 검증 함수(`talentSearchProjectValidate.js`)의 필수 필드 변경만 테스트 갱신.
- 나머지는 이 프로젝트 관례대로 로컬 dev 서버 + 브라우저로 수동 확인: 폼 필드가 정리됐는지, 카드 배지가 실제 프로젝트 상태에 따라 올바르게 바뀌는지(draft/approved+후보없음/수집중/목표달성), 프로젝트 상세 화면에서 4개 블록이 올바른 완료/진행/대기 상태로 보이는지, 기존 가상후보 화면과 설정 3화면이 여전히 정상 동작하는지(회귀).

## 알려진 한계

- "3단계 완료 → 4단계 진입" 기준을 "추천 인원이 목표인원 이상"으로 단순화했다 — 실제로는 목표를 못 채워도 사용자가 지금 있는 인원만으로 검토하고 싶을 수 있다. 이 경우 4단계 화면 자체는 3단계 상태에서도 항상 볼 수 있게 해서(배지 판정과 화면 접근은 별개), 배지가 "수집 중"이어도 그 아래 4단계 블록을 클릭해서 미리 볼 수 있게 한다.
- 마이그레이션(`role_title` NOT NULL 제거)은 `development` 브랜치에서 먼저 적용, `production` 반영은 사용자 확인 후 별도 진행(이 프로젝트 기존 원칙).
