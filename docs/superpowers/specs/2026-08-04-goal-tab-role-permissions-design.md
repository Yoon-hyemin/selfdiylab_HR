## 배경

현재 🎯목표 화면은 로그인 없이 완전히 공개돼 있어서, 회사·부서 목표를 아무나 만들 수 있다. 개인 목표만 마이페이지에서 로그인(이메일) 후 생성 가능하다.

사용자(비개발자 인사팀장)가 예전에 다른 세션에서 만들었던 목업을 기준으로, 목표 화면을 **관리자/부서장/팀원 역할에 따라 할 수 있는 일이 다르게** 만들고, **개인 목표 생성도 마이페이지가 아니라 목표 화면 자체**로 되돌리길 원한다. 브레인스토밍 과정에서 사용자가 명확히 한 것: 이건 "막기 위한 보안"이 아니라 "각자한테 맞는 화면/버튼을 자동으로 보여주기 위한" 역할 구분이다 — 부서별 목표·진행률은 원래도 전 구성원에게 공개해도 무방하다.

## 범위

- 목표 화면(🎯목표 탭)을 **전체 현황 / 부서 목표 / 개인 목표** 3개 서브탭으로 재구성
- `members`에 역할(`role`: 관리자/부서장/팀원) 추가, 인사팀이 구성원 등록 화면에서 지정
- 회사/부서 목표 생성에 역할 기반 서버 검증 추가 (지금까지 전혀 없던 것)
- 부서 목표에 범용 "파트" 태그 추가 (인사회계팀처럼 한 팀 안에 기능이 나뉘는 경우 대응)
- 목표 생성/체크 가능한 기간을 "이번 달 + 지난달"로 제한
- 개인 목표 생성 UI를 마이페이지 → 목표 탭(개인 목표 서브탭)으로 이동. 마이페이지에는 평가/원온원만 남김
- 팀당(파트가 있으면 파트별) 월 목표 개수 제한을 3개 → 5개로 완화
- **제외(다음 구획으로 분리)**: 지난달보다 더 오래된 목표의 히스토리 조회 화면, 개인/팀의 월별 달성률 추이 그래프. 데이터는 이미 `month` 단위로 영구 보존되므로 스키마 변경 없이 나중에 조회 화면만 추가하면 된다.

## 데이터 스키마 변경

```sql
-- members: 목표 화면에서의 역할
ALTER TABLE members ADD COLUMN role text NOT NULL DEFAULT '팀원';
-- '관리자' | '부서장' | '팀원' 세 값만 사용 (앱 레벨에서 검증, DB CHECK 제약은 걸지 않음 — 기존 컨벤션과 동일하게 자유 텍스트 취급)

-- okrs: 부서(조직) 레벨 목표를 팀 안에서 더 세분화하는 범용 태그
ALTER TABLE okrs ADD COLUMN part text DEFAULT '';
-- 레벨='조직'일 때만 사용. 빈 문자열 = 파트 구분 없는 팀. 값 예시: '인사', '회계' (자유 텍스트, 부서장이 입력)
```

개인(`개인` 레벨) 목표는 지금처럼 `parent_id`로 특정 부서 목표를 가리키므로, 그 부서 목표의 `part` 값을 그대로 물려받는 것으로 취급한다 — 개인 목표 자체에 별도 `part` 컬럼은 만들지 않는다.

## 권한 로직 (서버가 실제로 검사)

지금까지 `POST /api/okrs`는 레벨이 회사/조직이면 로그인 여부와 무관하게 아무나 호출 가능했다. 이번에 로그인(기존 `member_session` 쿠키)을 필수로 만들고, 역할을 검사한다.

| 액션 | 필요 조건 |
|---|---|
| 회사 목표 생성 | 로그인 + `role = '관리자'` |
| 부서 목표 생성 | 로그인 + `role = '부서장'` + `owner`(팀명)가 로그인한 본인의 `members.team`과 일치 |
| 개인 목표 생성 | 로그인(기존과 동일) + 연결하려는 부서 목표의 `owner`가 본인 팀과 일치 (기존엔 이 검증이 없어서 다른 팀 부서 목표에도 붙일 수 있었음 — 이번에 같이 막는다) |
| 위 전부의 조회(GET) | 기존과 동일하게 로그인 불필요, 전체 공개 |

부서 목표에 `part`가 있는 경우, 개인 목표 연결 시 "같은 팀"뿐 아니라 "어떤 부서 목표에 연결할지"는 본인이 목록에서 직접 고른다 — 어떤 파트 소속인지를 판별하는 별도 필드는 만들지 않는다(4인 이하 소규모 팀에서는 본인이 맞는 걸 고르는 것으로 충분).

**개수 제한**: 같은 팀·같은 달(그리고 `part`가 있다면 같은 파트)에 부서 목표가 이미 5개 있으면 생성 차단 (기존 3개 제한을 5개로 완화, 검증 쿼리에 `part` 비교 추가).

## 화면(UI) 구성

### 전체 현황 (로그인 불필요, 기존과 동일한 공개 성격)

- 이번 달 전사 달성률 요약 바
- 기업 목표 카드
- 부서 목표 카드 그리드 — 팀별로 실제 목표 제목 + 달성률(70%+ 초록 / 31~69% 주황 / 30% 이하 빨강)

### 부서 목표 (역할에 따라 다름)

- **상단**: 본인 소속 팀의 이번 달 목표를 길게(배너 형태)로 표시. `part`가 있는 팀은 파트별로 배너를 나눠서(각각 진행률·"+ 목표 추가" 버튼) 보여준다. `role = '부서장'`인 사람에게만 "+ 목표 추가" 버튼이 활성화된다(팀원 이하는 조회만).
- **왼쪽 2/3**: "우리 팀 팀원별 현황" — 팀원 각자의 개인 목표 제목 + 진행률(체크리스트 기반)을 나열. `part`가 있으면 파트별로 소제목을 나눠 그룹핑하고, 그룹 안에서는 **직급이 높은 사람이 위로** 온다 (정렬 기준 순서: 대표 > 부장 > 팀장 > 파트장 > 과장 > 대리 > 주임 > 사원 — 이 순서는 가정이라 스펙 리뷰 때 다르면 알려주시면 수정).
- **오른쪽 1/3**: 다른 팀 현황을 팀 이름 + 작은 게이지 + 퍼센트만 간단히 나열 ("참고용", "읽기 전용" 같은 설명 문구는 넣지 않는다).
- `role = '관리자'`는 이 탭에서 팀 목표를 만들 수 없다 — 조회만 가능(다른 팀원과 동일한 화면).

### 개인 목표 (로그인 필요)

- 상단에 "연결할 부서 목표" 드롭다운(본인 팀 소속의, 이번 달 또는 지난달 부서 목표만 후보로 뜸) + 제목 입력 + 생성 버튼
- 아래에 본인 개인 목표 카드 목록 — 카드마다 제목, 연결된 부서 목표(파트 배지 포함), 진행률, 체크리스트(체크/추가)
- 관리자 역할도 원한다면 개인 목표를 만들 수 있다 (역할과 무관하게 로그인한 사람 전원에게 열려있음)

## 월 편집 정책

- 회사/부서/개인 목표 **생성과 체크리스트 체크는 "이번 달 + 지난달"만 허용**한다. 그보다 오래된 달은 조회만 가능(수정 API 호출 시 서버가 400으로 거부).
- 이유: 월말이 주말과 겹치면 그날 체크를 못 할 수 있어서, 다음 달로 넘어간 뒤에도 지난달 몫을 정리할 여유를 준다.
- 목표 생성 화면의 "월" 선택은 자유 입력이 아니라 이번 달/지난달 중에서만 고르게 한다(현재는 아무 달이나 입력 가능한 상태).
- 두 달보다 더 지난 달의 조회 화면(히스토리)과 개인별 월별 달성률 추이는 이번 범위에 넣지 않는다 — 위 "범위" 절 참고.

## API 변경 요약

| 엔드포인트 | 변경 내용 |
|---|---|
| `POST /api/okrs` | 로그인 필수로 변경. 레벨='회사'는 `role='관리자'` 검사. 레벨='조직'은 `role='부서장'` + `owner`가 본인 팀과 일치하는지 검사. `part` 파라미터 추가(선택). 개수 제한 3→5, `part` 포함해서 카운트. 월은 이번 달/지난달만 허용 |
| `POST /api/my-goals` | 연결하려는 부서 목표의 `owner`가 로그인한 본인의 팀과 일치하는지 검증 추가. 월은 이번 달/지난달만 허용 |
| `POST /api/okr-tasks`, `PATCH /api/okr-tasks/:id` | 대상 목표의 `month`가 이번 달/지난달이 아니면 거부 |
| `GET /api/me` | 응답에 `role` 필드 추가 (지금은 `id/name/team`만 내려줌) |
| `PUT /api/members/:id` (구성원 수정) | `role` 필드 저장 가능하도록 확장 |
| `GET /api/public-data` | 변경 없음(이미 공개된 `okrs`에 `part` 컬럼만 자연스럽게 추가되어 내려감) |

## 화면 구성 변경 요약

- 목표 탭: 전체 현황 / 부서 목표 / 개인 목표 3개 서브탭으로 재구성 (기존엔 서브탭 없이 회사+부서 목표 나열 + 별도 "+새 목표 추가" 모달 하나뿐이었음)
- 마이페이지: 목표 관련 UI(개인 목표 생성/체크리스트) 전부 제거, 평가·원온원만 남김
- 구성원 관리 화면(인사 비밀번호 영역): 등록/수정 폼에 역할(관리자/부서장/팀원) 선택 추가

## 리스크 / 후속 과제

- 기존 27명 실제 구성원은 전부 `role` 기본값 '팀원'으로 들어가 있다. 관리자·부서장에 해당하는 인원은 인사팀장님이 구성원 화면에서 직접 지정해야 한다(자동 추론하지 않음).
- "직급 높은 사람이 위로" 정렬 순서(대표>부장>팀장>파트장>과장>대리>주임>사원)는 이번 스펙에서 가정한 값 — 실제 회사 직급 체계와 다르면 구현 전에 확인 필요.
- `part`는 완전 자유 텍스트라 부서장이 "인사"/"인사팀"/"HR" 등 다르게 입력하면 그룹이 갈라진다. 오탈자 검증은 이번 범위에 넣지 않음 — 문제가 되면 팀별 고정 파트 목록으로 후속 개선.
- 지난달보다 오래된 목표의 히스토리/추이 화면은 이번 범위 밖. 스키마(month별 영구 보존)는 이미 준비돼 있으므로 조회 화면만 추가하면 된다.
