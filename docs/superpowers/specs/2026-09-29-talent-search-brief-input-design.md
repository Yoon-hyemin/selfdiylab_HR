# 인재검색 "+ 새 인재검색" 입력 화면 간소화 — Claude Code 인수인계

> 이 문서를 Claude Code 세션에 그대로 붙여 넣고 시작한다. 먼저 저장소의 `CLAUDE.md`와 `HANDOFF.md`를 읽고, 그 문서의 작업 방식(한 조각씩 → 실데이터 확인 → `master` push 배포 → 수정)을 그대로 따른다.
> 사용자(윤혜민 인사팀장)는 비개발자다. 설명은 짧게, "무엇이 바뀌는지" 기준으로 한다.

## 1. 왜 바꾸나

현재 "+ 새 인재검색" 폼(`index.html`의 `renderNewTalentSearchForm`)은 입력칸이 13개이고, 사용자가 필수 / OR / 정확일치 / 제외 / 우대라는 검색엔진 문법으로 키워드를 직접 나눠 넣어야 해서 어렵다는 피드백이 있었다. 사용자가 시안을 보고 아래 흐름으로 확정했다.

**문장 한 줄 입력 → AI가 조건으로 정리 → 칩 몇 개 확인·수정 → 만들기**

## 2. 확정된 화면 흐름 (시안 기준)

### ① 문장 입력 화면
- 큰 입력칸 하나: "어떤 사람을 찾고 있나요?"
  - 예시: `대구(수성구·달서구·북구)에서 일할 경력 1년 이상 영상PD. 촬영과 편집은 꼭 할 줄 알아야 하고, AI 영상툴이나 After Effects, 커머스 경험이 있으면 우대. 최근 6개월 이상 경력 공백은 제외.`
- 버튼: **[조건 만들기]**(주 버튼), **[직접 입력할게요]**(빈 확인 화면으로 이동)
- 아래: "또는 지난 검색을 복제해서 시작". 기존 프로젝트 목록을 버튼으로 보여주고, 누르면 그 조건을 채운 확인 화면으로 간다. 제목에는 "(복사본)"을 붙인다.

### ② 정리 중 화면 (조건 만들기 직후)
- 입력한 문장을 위에 그대로 보여준다.
- "문장을 검색 조건으로 정리하고 있어요"와 함께 5단계 체크리스트를 보여준다: 지역 → 경력 → 꼭 있어야 해요 → 있으면 좋아요 → 있으면 안 돼요.
  - 끝난 단계는 체크 표시와 찾은 값, 진행 중인 단계는 스피너, 남은 단계는 "대기 중"이다.
  - 실제 AI 응답은 한 번에 오므로, 단계 표시는 응답 대기 중 연출이다. 응답이 오면 바로 ③으로 간다.
- AI 호출이 실패하면 오류 문구를 화면 안에 표시하고(`alert` 금지), [다시 시도]와 [직접 입력할게요]를 제공한다.

### ③ 조건 확인 화면 (왼쪽 폼 + 오른쪽 미리보기)
- **"문장에서 이렇게 읽었어요"**: 원래 문장에서 AI가 읽은 부분을 종류별 색으로 하이라이트한다.
  - 지역 = 보라, 경력 = 노랑, 직무 = 회색, 필수 = 초록, 우대 = 파랑, 제외 = 주황. 범례를 같이 보여준다.
  - 옆에 "← 문장 다시 쓰기" 링크를 둔다.
  - 하이라이트 구간은 AI 응답에 원문 구간(`spans`)으로 받는다(4절 참고).
- **검색 이름**: `YYYY.MM 지역 직무`로 자동 생성하고, 수정할 수 있다.
- **경력**: 버튼 선택 — `무관 / 신입 / 1년 이상 / 3년 이상 / 5년 이상 / 10년 이상`.
- **지역**: 시·도 드롭다운 + 구 버튼(다중 선택, "전체"는 단독). 기존 `locationDistricts` 값 형식을 그대로 쓴다.
- **칩 세 칸**:
  - **꼭 있어야 해요**(초록): 검색에 사용하고, 비슷한 말은 자동으로 같이 찾는다.
  - **있으면 좋아요**(파랑): 검색에는 안 쓰고 점수만 더한다.
  - **있으면 안 돼요**(주황): 단어는 검색에서 빼고, 조건은 이력 검토 때 거른다.
    - 이 칸의 칩에는 배지를 붙인다: `검색에서 제외`(단어) 또는 `이력 검토 때 확인`(예: "최근 6개월 이상 공백" 같은 조건).
  - 각 칸 아래에 입력창과 [추가] 버튼을 둔다. Enter로 추가하고(한글 IME 조합 중 Enter는 무시), 쉼표로 여러 개를 한 번에 넣을 수 있다.
  - 칩의 ×는 삭제다.
- **칩 끌어서 옮기기(드래그 앤 드롭)**: 사용자가 버튼 방식 대신 드래그로 명시적으로 선택했다.
  - 끄는 동안 원래 칩은 흐리게 표시한다.
  - 놓을 수 있는 다른 칸에는 점선 테두리와 "여기로 옮기기"를 보여준다. 칸 위에 올리면 진한 테두리와 "여기에 놓으면 옮겨져요"로 바뀐다.
  - `이력 검토 때 확인` 종류의 칩은 끌 수 없다.
  - 권장(선택): 키보드·터치 사용자를 위한 보조 수단 검토.
- **칩을 누르면**: 그 칸 아래에 "비슷한 말 편집" 패널이 열린다.
  - 비슷한 말 칩마다 ×로 삭제하고, 입력창과 Enter로 추가한다. [완료]로 닫는다.
  - `이력 검토 때 확인` 칩을 누르면 "검색 단어가 아니라서 비슷한 말을 붙이지 않는다"는 안내만 보여준다.
- 칩 영역 위 안내문: "칩을 끌어서 다른 칸에 놓으면 옮겨져요. 칩을 누르면 비슷한 말을 고칠 수 있고, ×는 삭제예요."
- **상세 조건 ▾**(기본 접힘): 학력(기존 5개 값 + "무관"), 최대 경력, 추천 목표 인원(기본 30), 정확히 이 단어로만 찾기(쉼표 구분, 대부분 비워 둠).
- 플랫폼 선택은 숨긴다. 지금 실행엔진이 있는 건 사람인뿐이라 `platforms: ['사람인']`으로 고정한다.
- **오른쪽 미리보기(sticky)**:
  - "이렇게 찾아요" 요약: 지역, 경력, 필수, 우대, 제외, 학력, 목표.
  - **사람인 검색어**: 실제로 확장이 입력할 OR / AND / NOT 칸 내용을 그대로 보여준다(3절 규칙 반영).
  - 안내: "있으면 좋아요는 검색어에 넣지 않고 점수에만 더해요."
- 하단: [취소], **[검색기준 만들기]** → 기존 `POST /api/talent-search-projects`로 저장한다.
- **기존 13칸 폼은 지우지 않는다.** 확인 화면에서 "기존 방식으로 입력" 링크로 갈 수 있게 남겨 둔다(1차 배포 후 실사용 피드백 보고 제거 여부 결정).

## 3. 저장 형식 매핑 (DB 마이그레이션 없음, 크롬 확장 수정 없음)

기존 `keywords` jsonb 구조(`include / or / exact / exclude / preferred`)를 그대로 쓴다. 비슷한 말만 새 키로 추가한다.

| 화면 | 저장 위치 |
|---|---|
| 입력한 문장 | `naturalLanguageBrief` (컬럼은 이미 있으나 지금까지 비어 있었음) |
| 꼭 있어야 해요 칩 | `keywords.include` (라벨) — 단, 아래 OR 규칙 참고 |
| 있으면 좋아요 칩 | `keywords.preferred` |
| 있으면 안 돼요 — 단어 | `keywords.exclude` |
| 있으면 안 돼요 — 이력 검토 조건 | `clarificationNotes`에 `{question: '피해야 할 조건', answer: '<칩 라벨>'}`로 저장. 질문 문구는 기존 데이터와 맞출지 확인할 것. 기존 예: "반드시 피해야 할 경력유형이나 업무환경이 있나요?" |
| 정확히 일치 | `keywords.exact` |
| 비슷한 말 | **새 키 `keywords.synonyms`** = `{ "<칩 라벨>": ["비슷한 말", ...] }` |
| 경력 | `experienceMinYears`(무관 = null, 신입 = 0, N년 이상 = N), `experienceMaxYears` |
| 지역 / 학력 / 목표 인원 | `locationDistricts` / `educationLevels`("무관"이면 빈 배열) / `targetRecommendCount` |

**꼭 바꿔야 할 서버 코드**: `handlers/talent-search-projects/index.js`의 POST가 `keywords`를 5개 키로 다시 조립하면서 다른 키를 버린다. `synonyms`를 통과시키고, `talentSearchProjectValidate.js`에 `synonyms` 형식 검증(객체, 값은 문자열 배열)을 추가하고 테스트도 추가한다.

**사람인 OR 칸 제약 (중요)**: 사람인 검색창은 OR / AND / NOT 칸이 하나씩이고, 확장(`chrome-extension/popup.js`의 `buildSearchTerms`)은 `or` 배열 전체를 한 OR 칸에 넣는다. 그래서 "필수 조건마다 비슷한 말 묶음"을 검색에 정확히 표현할 수 없다. 규칙은 다음과 같다.

- 비슷한 말이 있는 **첫 번째** 필수 칩은 `[라벨, ...비슷한 말]`을 `keywords.or`로 보낸다(= 이 중 하나 이상).
- 나머지 필수 칩은 라벨만 `keywords.include`로 보낸다. 그 칩들의 비슷한 말은 `keywords.synonyms`에만 저장하고, 채점과 AI 판단에 쓴다.
- 미리보기 검색어도 이 규칙대로 그려서 사용자가 실제 검색과 같은 내용을 보게 한다. 필요하면 "비슷한 말 묶음은 사람인 검색에 하나만 쓸 수 있어요" 안내를 추가한다.
- 기존 프로젝트를 복제할 때는 역변환한다: `or` 배열 → 첫 원소를 라벨, 나머지를 비슷한 말로 하는 필수 칩 1개. 사용자 기존 데이터(예: 2026.09 대구 영상PD의 `or: [AI, 영상편집]`)가 이상하게 보이지 않는지 실데이터로 확인할 것.

## 4. AI 정리 엔드포인트 (신규)

- `POST /api/talent-search-projects/parse-brief` `{ brief }` → 아래 JSON. `api/[...path].js`의 라우트 테이블에 추가하고, 권한은 기존 `requireTalentSearchAccess`를 쓴다.
- `handlers/_lib/geminiClient.js`에 `parseTalentSearchBrief(brief)`를 추가한다. 기존 `evaluateCandidateFit`와 같은 방식(`responseSchema` 지정 JSON 응답)으로 만든다.

```json
{
  "roleTitle": "영상PD",
  "region": "대구",
  "districts": ["수성구", "달서구", "북구"],
  "experienceMinYears": 1,
  "experienceMaxYears": null,
  "must":  [{ "label": "촬영", "synonyms": ["영상촬영", "카메라"] }, { "label": "편집", "synonyms": ["영상편집"] }],
  "nice":  [{ "label": "AI 영상툴", "synonyms": ["생성형 AI", "Runway", "Vrew"] }, { "label": "After Effects", "synonyms": ["에펙", "AE"] }, { "label": "커머스", "synonyms": ["이커머스"] }],
  "avoidKeywords": [],
  "avoidConditions": ["최근 6개월 이상 경력 공백"],
  "exact": [],
  "educationLevels": [],
  "spans": [{ "text": "대구(수성구·달서구·북구)", "type": "지역" }, { "text": "경력 1년 이상", "type": "경력" }]
}
```

- `spans[].text`는 원문에 그대로 있는 부분 문자열이어야 한다. 프론트에서 원문 안의 위치를 찾아 하이라이트하고, 못 찾으면 그 구간은 무시한다.
- 구 이름과 학력은 사람인이 쓰는 값만 허용하도록 프롬프트에 목록을 넣고, 서버에서도 한 번 더 걸러낸다(학력 = `TALENT_SEARCH_EDUCATION_LEVELS`).
- 모든 항목을 비워도 되게 만든다. 문장에 없는 걸 지어내지 않도록 프롬프트에 명시한다.
- 입력 문장에는 후보자 개인정보가 없고, 회사의 채용 조건만 Gemini로 간다(기존 AI의견보다 민감도 낮음).

## 5. 먼저 확인할 것: Gemini 502

2026-09-28에 실제 사이트에서 "AI의견" 버튼을 눌렀을 때 `ai-evaluate`가 502(`AI 판단을 받아오지 못했어요`)를 반환했다. 새 AI 정리 기능도 같은 Gemini 클라이언트를 쓰므로 1차 작업 전에 원인을 찾는다.
- Vercel 대시보드 → selfdiylab-hr → Logs에서 `Gemini 평가 실패` 로그의 실제 에러 메시지를 확인한다.
- 의심 지점: `geminiClient.js`의 `MODEL = 'gemini-3.6-flash'` 모델명 유효성, `GEMINI_API_KEY` 환경변수, 무료 등급 한도.
- 부수 개선: 실패 시 `alert()` 대신 화면 안에 오류를 표시한다(HANDOFF.md에 native 다이얼로그 때문에 검증이 막힌 이력이 있음).

## 6. 이번 조각(1차)의 범위와 완료 기준

**범위**: 2절 화면 + 3절 저장 매핑 + 4절 엔드포인트 + 5절 502 원인 수정.

**범위 밖 (다음 조각, 사용자와 따로 확인)**:
- 채점 정확도 수정(`scoreListCandidateJobFit`): 비슷한 말(`keywords.synonyms`) 반영, 공백·대소문자 정규화(`aftereffect` vs `Adobe After Effects` 불일치), 영문 짧은 키워드 단어 경계(`ai`가 mail·daily에 걸리는 문제), 필수/우대 가중치 구분, 4구간 → 연속 점수, "편집"과 "영상편집" 이중 집계, 저장된 태그의 `+26` 같은 잘린 값 제거. 이 조각에서 AI의견 프롬프트(`buildPrompt`)에도 `synonyms`를 넘겨 준다.
- 표 레이아웃 깨짐(학력 칸 세로 줄바꿈, 메모 칸 잘림), 성별·나이 열과 나이 정렬 기본 숨김 검토.

**완료 기준 (CLAUDE.md 방식)**:
1. `master` push → Vercel 배포 사이트에서 사용자가 실제 채용 건 문장으로 조건을 만들어 저장한다.
2. 저장된 프로젝트를 크롬 확장 "목표 인원 채우기"로 돌렸을 때, 사람인 검색창의 OR / AND / NOT 칩이 미리보기 검색어와 똑같이 들어간다.
3. 기존 프로젝트 복제가 정상적으로 칩으로 보인다.

## 7. 참고: 시안

- 사용자가 확인한 클릭형 시안은 claude.ai의 "새 인재검색 간소화 시안" 아티팩트다(비공개라 Claude Code에서는 열리지 않음 — 위 2절에 내용 전부 정리함). 화면 스타일은 기존 앱(흰 카드, 초록 주 버튼, 둥근 칩)을 그대로 따른다.
- 칩 색: 필수 `#e7f6ee` / `#0b5e34`, 우대 `#eaf1fd` / `#1a4aa8`, 제외 `#fdeee7` / `#8f3413`.
- 비슷한 말 기본 사전(시작값, AI 결과가 비었을 때 보조로 사용 가능): 편집 → 영상편집·편집자 / 촬영 → 영상촬영·카메라 / After Effects → 에펙·AE / 프리미어 → Premiere Pro / 커머스 → 이커머스·쇼핑몰 / 쇼츠 → 숏폼·릴스.
