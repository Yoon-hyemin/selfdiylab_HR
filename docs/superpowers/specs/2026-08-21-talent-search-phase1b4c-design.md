# 인재검색 Phase 1B-4c — 가상 후보 3명 미리보기

- 작성일: 2026-08-21
- 선행 문서: `docs/superpowers/specs/2026-08-21-talent-search-phase1b4a-design.md`(초안 상태), `docs/superpowers/specs/2026-08-21-talent-search-phase1b4b-design.md`(버전 이력+복구), `docs/superpowers/specs/2026-08-19-talent-search-phase1b1-policy-schema-design.md`(정책 스키마)
- 관련 기존 파일: `인재검색_자동화_마스터프롬프트_원본.md` 5~7장(채점 로직 원본), `index.html`의 `loadAndRenderTalentSearchPolicy()`

## 배경

이 문서로 Phase 1B(평가·검색 기준 관리센터)의 마지막 조각을 다룬다. 1B-1~1B-4b에서 정책 값(Level1/공통40점/직무60점/근거수준/임계값·하루상한)을 보고 고치고 초안으로 검토하고 이력을 확인하는 것까지 다 만들었는데, 정작 "이 값들을 바꾸면 실제로 어떤 차이가 생기는지"는 숫자만 보고 상상해야 했다. 아직 실제 이력서 평가 엔진(Phase 2+)이 없어서 진짜 후보 데이터로 확인할 방법이 없으므로, 원본 명세서의 채점 공식을 그대로 이용해 미리 정해둔 가상(합성) 후보 3명에 지금 정책을 적용해보는 가벼운 시뮬레이션을 추가한다.

## 사용자 결정 (이번 세션 확인)

- 가상 후보 3명은 **코드에 고정된 3가지 유형**(강함/애매함/약함)으로 미리 박아둔다 — 사용자가 입력/편집하는 기능은 만들지 않는다.
- 계산은 **전부 화면(자바스크립트)에서** 한다 — 새 API를 만들지 않는다. 이미 화면이 갖고 있는 활성/초안 정책 값에 계산식을 그대로 적용한다.
- 화면은 기준 관리센터 **맨 아래에 항상 보이는 섹션**으로 추가한다(버튼으로 열어보는 방식 아님).

## 범위

**포함**: 가상 후보 3명 고정 데이터, 채점 시뮬레이션 계산 함수(Level1 판정, 공통40점/직무60점 점수, 총점, 최종판정), 활성 정책 기준 결과 + (초안이 있으면) 초안 정책 기준 결과를 나란히 보여주는 화면 섹션.

**포함 안 함**: 실제 이력서 평가 엔진(Phase 2+), 직무별 필수/우대/제외조건 하드필터(아직 검색 프로젝트 자체가 없음 — 1C~1D 이후), 가상 후보 데이터 편집 UI, 서버 API 신설.

## 가상 후보 3명 (고정 데이터)

| | 후보 A (강함) | 후보 B (애매함) | 후보 C (약함) |
|---|---|---|---|
| 이력서 최근 업데이트 | 20일 전 | 140일 전 | 220일 전 |
| 단기근속 횟수(최근 5년) | 0회 | 1회 | 3회 |
| 경력 공백 | 0개월 | 8개월 | 15개월 |
| 근거수준 패턴(공통40/직무60 항목에 순서대로 순환 적용) | 명확,명확,부분,명확,명확 | 부분,약함,부분,약함,부분 | 약함,없음,없음,약함,없음 |

근거수준은 **항목 이름이 아니라 배열 순서로** 매칭한다 — 공통40점/직무60점 항목은 자유롭게 추가/삭제되므로, 이름 기반 매칭은 항목이 바뀌면 깨진다. 순서 매칭은 항목 개수가 바뀌어도 패턴을 순환시켜 항상 값을 매길 수 있다(예: 항목이 7개면 패턴을 앞에서부터 다시 반복).

후보 B가 핵심이다 — 원본 명세서 기본값(이력서 확인필요 180일, 경력공백 확인필요 12개월) 기준으로는 Level1이 "확인 필요"가 되지만, 관리자가 그 기준을 조정하면 판정이 바뀔 수 있다. 이게 이 미리보기가 보여주려는 핵심 가치다.

## 계산 로직

### Level 1 판정 (단순화)

원본 명세(5장)의 세부 예외 처리(계약만료·구조조정 등 단기근속 예외사유, 경력공백 사유 확인)는 실제 이력서 텍스트가 있어야 판단 가능해서 이 시뮬레이션에서는 다룰 수 없다 — 대신 각 항목을 아래처럼 단순화한다.

```
이력서 업데이트: 경과일 ≤ passWithinDays → PASS
                 경과일 ≤ verifyWithinDays → VERIFY
                 그 외 → FAIL
단기근속: 횟수 ≥ countThreshold → VERIFY, 아니면 PASS
경력공백: 개월 < ignoreUnderMonths → PASS
          개월 < verifyUnderMonths → VERIFY
          그 외 → VERIFY (원본 명세도 "설명 필요"이지 자동 FAIL은 아님)

종합 판정 = 셋 중 하나라도 FAIL이면 FAIL, 하나라도 VERIFY면 VERIFY, 전부 PASS면 PASS
```

FAIL은 이력서 업데이트 기준에서만 나온다(원본 명세에서 유일하게 "180일 초과 = FAIL, 자동 추천 제외"로 명시된 항목) — 단기근속·경력공백은 "제외 검토"/"설명 필요" 수준이라 이 시뮬레이션에서는 VERIFY로 다룬다.

### 공통 40점 / 직무 60점 점수 (원본 명세 6장 공식 그대로)

```
항목점수 = 항목배점 × 근거계수(없음/약함/부분/명확 = policy.evidenceCoefficients 값)
항목점수는 policy.roundingRule.unit(기본 0.5) 단위로 반올림, 정확히 중간이면 올림(roundUp)
그룹 총점 = 반올림된 항목점수의 합
의미있는 근거 개수 = 근거수준이 "부분" 또는 "명확"인 항목 수(공통40+직무60 합산)
```

### 최종 판정

```
Level1 = FAIL          → 제외
Level1 = VERIFY         → 확인 필요
Level1 = PASS 이면서
  총점 ≥ thresholds.totalScoreMin AND
  직무60점 ≥ thresholds.jobFitScoreMin AND
  의미있는 근거 개수 ≥ thresholds.minMeaningfulEvidenceCount
                        → 추천
그 외                    → 확인 필요
```

직무별 필수/제외조건 하드필터는 아직 존재하지 않으므로(1C~1D 이후) 이 시뮬레이션에는 없다.

## 화면

기준 관리센터의 5개 카드(+초안 배너/비교, 있으면) 아래에 새 섹션 "가상 후보 미리보기"를 추가한다. 후보 3명을 표로 보여준다:

| 후보 | Level1 | 공통40점 | 직무60점 | 총점 | 판정(기존) | 판정(초안) |
|---|---|---|---|---|---|---|

초안이 없으면 "판정(초안)" 열은 안 보이고 "판정" 하나만 보인다. 판정이 기존→초안 사이에 달라지면 그 셀을 눈에 띄게 표시한다(예: 색상 강조).

계산은 화면에 이미 있는 `tsPolicy`(카드가 보여주는 값 — 초안 있으면 초안, 없으면 활성)와 활성 정책(초안이 있을 때만 비교 대상으로 필요) 양쪽에 대해 순수 함수로 실행한다. 새 API 호출 없음 — `loadAndRenderTalentSearchPolicy()`가 이미 받아온 데이터를 재사용한다.

## 리스크 / 후속 확인 사항

- 이 시뮬레이션은 실제 채점 엔진이 아니라 **"정책이 대략 어떻게 작동하는지 감을 잡는" 도구**다 — 진짜 이력서 평가와 결과가 다를 수 있다는 걸 화면에 짧게 안내한다.
- 근거수준 패턴을 "순서"로 매칭하기 때문에, 관리자가 항목 순서를 바꾸면(현재 UI에는 순서 변경 기능이 없음 — 추가/삭제만 가능) 같은 후보라도 결과가 달라질 수 있다. 지금 UI 범위에서는 발생하지 않는 경우라 문제되지 않는다.
- Level1 시뮬레이션의 단순화(예외사유 무시)는 명시적으로 문서화해서, 나중에 실제 평가 엔진과 결과가 다르다고 헷갈리지 않게 한다.
